## Архитектура

Система построена на базе микросервисной архитектуры.

### Выделенные сервисы

[event-service] - отвечает за CRUD событий и категорий, высчитывает события в определенном радиусе
[location-service] - отвечает за CRUD локаций
[request-service] - отвечает за CRUD запросов на участие в событиях
[compilation-service] - отвечает за CRUD подборок событий
[user-service] - отвечает за CRUD пользователей

### Межсервисное взаимодействие

Межсервисное взаимодействие обеспечивается OpenFeign.
Стабильность соединения обеспечивается resilience4

### Внутренний API (Inter-service Communication)
Внутренний API используется исключительно для обмена данными между сервисами внутри контура системы и закрыт от внешнего мира.
/api/events/{eventId}/users/{userId} = поиск события по id и initiatorId
/api/events/{eventId} - поиск событий по id
/api/events/full - поиск всех событий по id, возвращает EventFullDto
/api/events/short поиск всех событий по id, возвращает EventShortDto

/api/requests/{eventId} - возвращает количество подтвержденных заявок на участие в событии
/api/requests/confirmedByEventIds - возвращает список подтвержденных заявок на участие в событии
/api/users - возвращает Map пользователей по предоставленном списку ids
